# AnimeBoot Neo Debug (2610.3)

**用一个可视化画布，设计属于自己的 Windows 开机静图与全彩动图。**

AnimeBoot Neo Debug 是由 **原心** 开发的 Windows 开机画面设计工具。你可以自由组合图片、角色、Logo、文字和倒计时控件，制作一张或多张开机静图；也可以加入 GIF、视频或 PNG 帧序列，让电脑在进入 Windows 之前播放全彩无声动画。多画布与多动画支持按次顺序轮换，设计结果可以保存为工程，也可以打包成包含素材的分享包。

项目同时提供 **UEFI 与传统 BIOS/Legacy 两条启动路径**：UEFI 使用保持原始签名的 Fedora 启动组件，Legacy 使用独立的 GRUB4DOS/GRUB2 文件启动链。支持 Windows 7,8,8.1,10,11或更高版本，基于x86架构构建，支持32位/64位 Windows 系统。UEFI启动下，无需干预即可通过主板UEFI安全启动。

当前版本为 **2610.3 开源测试版**，仅提供**中文界面、中文交互与中文教程**。本仓库呈现的是原心与 **Nomen（helloyork）合作之前**的作品及其当前架构。接下来计划将项目合作并入新架构，由 **Nomen（helloyork）继续推进新架构的改进与主要维护**；该计划代表本项目将停留在此Debug旧版架构，也**不会继续单独维护更新**。

本项目自有代码采用 **GPL-3.0-or-later**。免费开源，欢迎学习源码、研究启动原理，以及在遵守许可的前提下修改和分发。

### 自由设计静图

编辑器采用 Qt/PySide2，提供画布预览、图层列表、网格与辅助线、缩放及适应窗口等操作。图片和文字可以独立调整位置、大小、旋转角度及层序；对象有八个缩放控制点，并支持保持正方形。

你可以制作简洁的 Logo 画面、角色主题、文字欢迎页，也可以把照片与装饰组合成完整背景。中文文字在制作时会被合成到背景图中，不依赖 GRUB 临时加载中文 TrueType 字体。可选用的字体由本程序扫描系统与当前用户安装的字体，并筛选所有中文字体；选用的字体仍须包含实际使用文字的字形。

静图时长可设为 **0—180 秒**。将时长设为 0 秒会跳过静图阶段：启用动图时直接播放动图，否则直接进入 Windows。这主要供只想显示动图的用户使用，也意味着没有静图阶段按 Esc 跳过动图的机会。

### 多画布：每次开机换一张

在预览区上方选择当前画布，并通过“新增、复制、删除”管理列表。编辑器始终只显示一张画布，不需要同时操作多个编辑窗口。

- 所有画布共用输出分辨率、静图时长、启动设置和动画列表。
- 每张画布保存自己的图片、文字、图层，以及倒计时样式、位置和颜色。
- 开机按列表顺序显示 A → B → C → A，最多支持 8 张。
- 编辑时选中哪张画布，不会改变实际开机轮换的起点；安装后从列表第一张开始。
- 制作时会读取制作一开始时的工程快照，也就是说制作期间切换画布或编辑内容，不会改变正在输出的结果，本次制作阶段中出现的画布等修改将在下一次制作时才能生效。

制作时各画布分别合成为背景图，配套主题数据仍由同一份主启动配置控制。完全相同的背景与控件资源可以共用，减少启动分区中的重复文件。

### 丰富的倒计时与静图交接

除了“不显示”，本版提供白点圆环、填充进度条、数字倒计时、星形/心形/短线刻度圆环和贴图进度条。这些是 **GRUB 主题中的动态倒计时控件**，用于提示静图剩余时间；全彩视频动画则由后续 Linux 播放环境负责。

未启用动图时，可选择两种进入 Windows 的过渡方式：

- **无感融入**：尽量保留静图背景，让 Windows 的启动转圈在同一背景上出现。在 UEFI 下，且**所有静图画布均不显示倒计时控件**时，采用外层等待与菜单退出机制，避免 GRUB 菜单超时清屏导致倒计时结束时黑闪一次屏幕，影响用户体验。
- **清屏过渡**：静图结束后清为黑屏，再启动 Windows。

若任意画布显示了倒计时控件，整套工程将改为使用 GRUB 菜单倒计时以便正常显示倒计时控件；而此时的“无感融入”在倒计时结束时会短暂黑闪后再恢复背景。用户选择显示控件时会提示这一交接差异。Legacy 的 Windows 加载器则很可能重新设置显示模式，因此不承诺其具有与 UEFI 完全相同的背景连续效果。

**开启动图后，上述静图过渡选项不生效**：静图结束后会强制清为黑屏，再进入 Linux 播放环境。在静图阶段按 Esc 则直接进入 Windows，不额外执行这次黑屏过渡。Esc 跳过仅在静图阶段有效，本版没有在动图播放期间加入任何按 Esc 键跳过动图的功能。

### 全彩无声动画与顺序轮换

动画输入支持 GIF、APNG、动态 WebP，MP4、MKV、MOV、AVI、WebM 等常见动图及视频文件格式，以及 PNG 帧文件夹。用户可以设置输出尺寸、画面适配方式、抽帧帧率、播放帧率、帧数上限和循环次数。抽帧帧率与播放帧率分别控制，方便在体积、时长与流畅度之间灵活调整。

动画提供 **QOI 无损编码**与 **JPEG 编码**。前者保留无损图像，后者可通过质量设置控制容量，并使用分块压缩组织播放数据。当前单段动画最多处理 6000 帧；实际播放能力仍取决于分辨率、编码与目标机器。

除主动画外，可添加最多 7 段追加素材，组成最多 8 段的顺序轮换列表。某段动画播放成功开始时才意味着已经将下次开机时要播放的序号设定到下一段，最后一段播放结束后，下次播放会回到第一段（主动画）循环往复。静图轮换与动图轮换各自维护序号，因此可以自由组合多静图与多动画。

轮换只按次数进行，**没有按天或随机轮换功能**。在静图阶段按 Esc 不会推进动图序号；动画结束后的接力重启也不会导致轮换多前进一步。

### 容量估算、制作与安装

动画轮换窗口会按当前选定编码估算**主动画与全部追加动画**的容量，并连同静图、共享内核及启动资源，与启动分区可用空间比较。已有安装中可清理的所属资源会计入可回收空间，不会简单把它们当成永远占用的额外容量。

素材与参数未变时可以复用已通过的估算，不必在勾选启用时重复计算；追加的动画列表发生文件/文件夹条目改变后需要重新估算。估算用于制作前判断，安装时仍会以实际生成的文件和当前空间进行最终检查。

“开始制作”会先生成安装资源，再进行自动安装。安装前检查当前引导模式、Windows 启动文件、空间及必要的系统状态；安装过程中会记录本工具参与的修改及可恢复的文件清单。遇到可恢复的安装问题，可通过继续制作按钮复用已经生成的结果。

“禁用”用于恢复原 Windows 入口，再清理本工具所属文件、资源目录与备份记录。请通过本程序禁用开机画面，避免手动操作启动分区、删除 Windows 入口备份或安装记录后失去恢复依据。安装与禁用需要管理员权限，普通画布编辑不需要修改启动分区。

### 保存工程与分享包

**工程文件**适合在本机继续编辑，保存画布、启动参数、轮换列表及素材引用；**分享包**在工程基础上打包所需外部资源，更适合把设计交给另一台电脑或其他用户使用。

顶部“分享包”按钮，提供导入与导出。多画布、每张画布的倒计时属性、多动画轮换及相关参数均纳入保存与分享流程。导出时可选择是否包含动画素材；导入后应保留解包资源目录，避免删掉工程仍在引用的图片、字体或动画。

仓库中的 [双画布与双动画示例](examples/双画布与双动画.anbtheme) 可用于测试分享包的使用操作。分享前请确认图片、字体与视频的授权，程序打包资源并不等于取得其再分发许可。

### 调试与当前制作信息

“显示调试信息”用于**启用动图时的播放诊断**：动画播放结束后，在播放器的显示画布上展示两页信息，每页 8 秒，然后重启接力进入 Windows。诊断画面包含目标/实际平均帧率、解码状况与帧数、初始化和播放各阶段耗时等信息。关闭该选项可以隐藏掉这两页的诊断信息展示；纯静图模式在开启该选项的情况下，也不会显示该播放诊断页。

正常启动路径尽量保持画面干净，减少 GRUB 和 Linux 的文字输出。这不意味着工具能控制主板自检画面或屏蔽所有启动异常。界面中的“当前制作/安装信息”是 Windows 端输出的制作与安装日志，与开机播放器的诊断页是两个不同功能；日志自动跟随新信息，用户拖动滚动条查看时会暂停跟随。

## 动画制作与播放效果

本版围绕**快速制作、快速准备首帧、连续播放**优化压缩、解码与显示流程，让高分辨率全彩动画组被快速制作、流畅播放。

- **制作端并行处理**：视频使用 FFmpeg 抽帧，结合可用 CPU 与输入类型安排并行任务；图像缩放、编码等阶段使用有界并发，兼顾处理速度与内存占用。
- **播放数据预先准备**：安装前完成抽帧与编码，开机画面播放时不解码原始视频容器。
- **首帧优先**：播放环境先准备首帧并开始显示，无需等待整段动画全部解码。
- **分块与预取**：JPEG 动画按块组织并支持并行解压，播放器结合预取与解码工作线程，减少连续播放时的等待。
- **内存播放**：GRUB 将本次选中的播放环境和动画加载到内存，播放器从内存取得数据，不在播放途中扫描硬盘或读取原始视频，这使得加载动画的耗时很少，用户对加载时间几乎没有感觉。
- **资源按需加载**：多动画轮换共用一份内核，每次只载入选中的动画环境，不把所有轮换动画同时塞进内存。

实际体验中，动画帧制作效果与播放准备速度已得到实机验证。但实机表现的速度仍与机器本身的 CPU、内存情况和动画尺寸、编码和输入格式有关；虽然效果很好，但是并不能以“固定秒数”或“所有机器达到指定 FPS”作为保证。且本项目的动画播放器在性能上也不承诺在机器的显示设备上能支持垂直同步或无撕裂。

## 启动原理与安全启动

### UEFI：官方签名逐级验证

```text
UEFI 固件
  └─ Fedora shim（微软签名，作为本工具的启动入口）
       └─ Fedora 签名 GRUB2
            ├─ 显示静图 → 原 Windows Boot Manager → Windows
            └─ 显示静图 → Fedora 签名 Linux 内核 + 播放环境
                            → 播放动图 → 重启接力 → Windows
```

本项目使用从 Fedora 官方软件包提取的 **shim、GRUB2 与 Linux 内核**，并保持这些签名二进制的原始字节。UEFI 固件验证 shim 的微软签名；shim 与后续加载器按受信任密钥验证 GRUB 和内核。这是保留安全启动的基础，原理可参阅 [Fedora Secure Boot 官方说明](https://fedoraproject.org/wiki/Secureboot)。

**在固件信任所需微软第三方 UEFI CA、且组件未被当前撤销策略拒绝的机器上，可以保持 Secure Boot 开启，无需用户自行签名、导入自定义密钥或登记 MOK。** 这条路线不依赖关闭安全启动，也不依赖把自行编译的未签名 EFI 程序伪装成已签名程序。

这里的“签名启动链”指核心加载器与内核的逐级签名验证。用户设计的背景、动画，以及本项目生成的 initramfs 和用户态播放器，并没有因此获得独立的固件签名认证。主板信任库、dbx/SBAT 撤销策略与固件实现会影响能否启动，不能将“官方已签名”理解为任何机器、任何未来策略下都必定接受。

Windows 原始 `bootmgfw.efi` 在安装时保存为接力与恢复入口；本项目不提供、重新签署或替代其内部实现。本项目的 UEFI 修改路径不会操作或修改 `EFI/BOOT/bootx64.efi`，具体实际部署位置见 [启动分区文件详细说明](教程/启动分区文件详细说明.md)。

### Legacy：独立文件启动链

```text
BIOS/Legacy 固件
  └─ 本项目微型 MBR → 原活动分区引导扇区
       └─ GRUB4DOS 文件桥接 → GRUB2 BIOS 核心
            ├─ 显示静图 → 原 Windows bootmgr → Windows
            └─ 显示静图 → Linux 内核 + 播放环境
                            → 播放动图 → 重启接力 → Windows
```

Legacy 路径采用开源 GRUB4DOS 与配对版本的 GRUB2。较大的核心与播放资源保存为启动分区内的普通文件，不要求在首分区前的磁盘间隙中塞入大型 GRUB 核心或动画。微型 MBR 安装只替换引导代码区，保留磁盘签名与分区表，并保存恢复材料。

**动画后的 Windows 一次接力、多静图与多动图轮换均由 GRUB 管理状态**，使用固定的 `AnimeBootNeo/bootstate.env` 环境块文件。Linux 与播放器从内存工作，不负责写磁盘播放标记，也不需要为这一职责额外加载 NVMe/SATA 驱动包。Legacy 不属于 UEFI Secure Boot 的验证范围，不能称作“安全启动签名的 BIOS 链”。

## 系统与架构支持

程序按 **Windows 7、8、8.1、10、11 的兼容目标**构建，使用 **x86 / 32 位 Python** 生成 Windows 可执行程序，可运行于符合依赖要求的 32 位或 64 位 Windows。未来的 Windows 版本暂不能保证一定能使用，应以实际兼容性测试为准。

| 层级 | 支持范围 |
| --- | --- |
| Windows 设计工具 / EXE | x86 构建；可在 32 位与 64 位 Windows 使用 |
| UEFI 下的目标架构 | **x86-64 UEFI**；当前没有内置 IA32 UEFI 或 ARM64 启动资源 |
| Legacy 静图 | BIOS/MBR 文件启动路径，需符合工具支持的磁盘与文件系统布局 |
| Legacy 动图 | 使用 x86-64 Linux 内核，**CPU 必须具备 64 位执行能力，即使 Windows 本身是 32 位** |
| 安全启动 | 适用于受信任的 x86-64 UEFI 签名链；不适用于 BIOS/Legacy |
| 显示输出 | 使用固件、GRUB 与 Linux 的可用显示能力来输出，不能调用GPU；**实际可支持的最高分辨率和显示表现取决于机器本身情况** |

**32 位应用兼容不等于 32 位 UEFI 支持。** 系统版本、Windows 位数、CPU 能力和固件架构需要分别判断。动画显示需要足够内存与启动分区空间；加密的设备/系统盘须满足安装预检查，仅暂停 BitLocker 保护不等同于完成解密，可能无法成功完成制作，请通过界面上的反馈信息与操作指导来继续操作。

## 快速开始

1. 阅读 [中文教程目录](教程/阅读顺序.md)，确认目标机器的引导方式与架构。
2. 启动程序，在“静图”页设置分辨率、时长与倒计时，并在画布中编辑图片和文字。
3. 需要多静图时，通过当前画布管理栏新增或复制画布。
4. 需要动图时，选择并启用主动画，设置抽帧、编码与播放参数；需要轮换时添加追加动画并完成容量估算。
5. 在“开始制作”页选择 GRUB、诊断及适用的静图过渡设置，开始制作并按提示安装。
6. 制作完成后保存工程；需要分享时导出分享包。重启实测启动画面及 Windows 交接情况。
7. 想要完全恢复原本的 Windows 启动链时，需通过“禁用”完成恢复与清理。

这是一款会修改启动入口的测试工具。首次实测前请准备可用的系统恢复途径，并保留安装器生成的备份；详细操作与故障处理以教程及程序提示为准。

## 开发环境与 EXE 构建

### 固定构建环境

使用 **Windows Python 3.8.10 32 位**，依赖版本见 [requirements-build.txt](requirements-build.txt)。

| 依赖 | 版本 |
| --- | --- |
| Python | 3.8.10，x86 / 32 位 |
| PyInstaller | 5.13.2 |
| PySide2 | 5.15.2.1 |
| Pillow | 9.5.0 |
| imageio-ffmpeg | 0.4.9 |
| fonttools | 4.47.0 |

这些版本用于当前 Windows 兼容目标。`build.py` 会检查 Python 架构、版本与 PySide2 版本；不要直接用 64 位 Python 或任意新版本依赖替换后，仍将结果视为同一兼容构建。

### 从源码运行

在工程根目录打开 PowerShell，确认 `python` 指向上述 32 位 Python：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-build.txt
python app.py
```

若不使用虚拟环境激活，也可以显式调用环境中的解释器：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe app.py
```

### 构建目录版

```powershell
python build.py
```

输出：`dist/AnimeBoot Neo Debug/AnimeBoot Neo Debug.exe`。

分发或移动目录版时应复制整个输出目录，保留旁边的资源、DLL 与许可证文件。

### 构建单 EXE 版

```powershell
python build.py --onefile
```

输出：`dist/single/AnimeBoot Neo Debug.exe`。

单 EXE 运行时会将所需资源展开到临时目录，首次启动与安全软件扫描耗时可能不同于目录版。两种打包方式使用同一应用代码与启动资源；单文件打包不会免除第三方许可及对应源码的分发义务。

上述命令构建的是 **Windows 制作工具**，不是重新编译 Fedora 签名 shim、GRUB 或 Linux。签名启动组件从随包资源读取，保持官方原始字节。
