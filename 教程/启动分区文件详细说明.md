# 启动分区文件详细说明

assets 是制作工具使用的原材料；InstallPayload 是未绑定目标的制作结果；安装时建立一个目标模式绑定的临时副本，把其 `files/` 中的文件部署到真实启动分区。assets的46个所需BIOS模块按依赖嵌入核心，不作为模块目录复制到启动分区。动画开启与否、多画布数量影响以下文件。

| 通用制作目录 | 内容与实际使用 |
| --- | --- |
| boot.img | 本项目512字节微型MBR，资源管理器可能显示1KB；Legacy仅写LBA0前440字节，保留磁盘签名/分区表/55AA。只加载原活动分区VBR；不占首分区前间隙。UEFI不用。 |
| core.img | 所选配对版本的GRUB2 BIOS核心及必要模块、短定位配置；安装时按目标卷UUID重建。中间产物，与lnxboot.img合入grub2.lnx，不作为独立文件安装。不是Linux内核。 |
| legacy.bootmgr | 上游GRUB4DOS加本项目菜单与静默处理；Legacy复制为启动卷根目录bootmgr，原Windows bootmgr另存供恢复及接力。上游来源见官方组件指南。 |
| manifest.json | 当前版标识、启动模式绑定、实际资源清单及SHA256/大小、所选GRUB版本、动画条目、静图数量/模式及过渡策略。仅在制作/安装准备目录使用，不复制到启动分区。 |
| files/ | 真正需要部署的普通启动文件。绑定后只保留适用于UEFI或Legacy的那一部分。 |

| files内相对路径 | 条件与作用 |
| --- | --- |
| AnimeBootNeo/theme/back.png / style.txt | 只有一张画布时，保留简洁的单张命名。背景是所有图片、文字、层序的合成图；style保留GRUB倒计时布局。 |
| AnimeBootNeo/theme/style-00.txt、style-01.txt… | 多画布时每张一份style，分别引用背景及独立倒计时控件属性。多份style是主题数据，不是多份grub.cfg。 |
| AnimeBootNeo/theme/back-00.png、back-01.png… | 每张画布合成的背景；字节完全相同的PNG只保存一份，多份style引用它。当前编辑画布与开机起始序号无关；安装从列表第一张开始。 |
| theme/tick[-编号].png、circle-center[-编号].png | 圆环系列才需要。tick是白点/星/心/短线的贴图；circle-center是圆形控件必需的1×1透明中心，不是可见主Logo。相同资源可共用。普通圆环单画布仍使用tick.png/circle-center.png。 |
| theme/bar-track[-编号]_*.png、bar-fill[-编号]_*.png | 贴图进度条才需要的两组九宫格贴图；相同整组资源共用。普通填充条/数字/不显示无需这组图片。 |
| AnimeBootNeo/bootstate.env | 仅“启用动图或多静图”需要，固定1024字节。neo_once控制动画后一次进Windows；neo_rotation控制下一段动图；neo_static_rotation控制下一张静图。三个变量都是GRUB层写入，范围分别0/1、0—7、0—7。无需随机定位文件。单张静图且未开动图则没有它。 |
| AnimeBootNeo/bzImage | 仅开启动图需要，Fedora官方签名Linux内核，UEFI/Legacy同一份。静图只用GRUB，不载入Linux。 |
| AnimeBootNeo/anim_initramfs | 动图开启但未启用多动图轮换时的一份内存根文件系统，包含本项目init、播放器、编码帧。GRUB预载到RAM，Linux不用从磁盘取视频，不写磁盘。 |
| AnimeBootNeo/animations/00.initramfs、01.initramfs… | 多动图时各段独立initramfs，00是主动画。GRUB选择其中一份；所有文件都占启动分区空间，因此估算必须全部相加。不会同时把所有initramfs都加载到RAM。 |
| AnimeBootNeo/grub.cfg | 仅Legacy绑定后部署；唯一完整主配置。选择static theme、动画initramfs、Windows过渡及环境块接力。 |
| AnimeBootNeo/grub2.lnx | 仅Legacy；官方lnxboot.img+生成的BIOS核心，为GRUB4DOS提供Linux启动协议外形，不是播放器内核。 |
| AnimeBootNeo/unicode.pf2 | 仅Legacy加载的GRUB位图字体；签名UEFI不能载入外置PF2，中文已合成进背景PNG。 |
| EFI/fedora/grub.cfg | 仅UEFI绑定后部署；唯一主配置，Fedora签名GRUB的固定prefix在这里。从fw_path获得实际启动设备，没有search随机文件。单文件嵌套菜单用于Esc返回外层接Windows。 |
| EFI/Microsoft/Boot/bootmgfw.efi | Fedora微软签名shim，按入口需求重命名，字节未改。 |
| EFI/Microsoft/Boot/grubx64.efi | 默认/备用中当前选择的Fedora签名GRUB，只部署所选那份。其Legacy核心采用配对的同一发行版本。 |
| EFI/Microsoft/Boot/mmx64.efi | 与shim配套的官方MokManager辅助组件，不要求正常路径下用户登记自签名。 |

安装程序还保留真实Windows入口：UEFI由GRUB chainloader `EFI/Microsoft/Boot/bootmgfw.efi_ANBAK`；Legacy由ntldr加载`AnimeBootNeo/windows.bootmgr`。回滚备份及安装记录 `AnimeBootNeo.Backup/state.json` 供当前版验证与完整禁用恢复Windows。它们由安装器生成，不是额外动画素材。

本版不管理EFI/BOOT/bootx64.efi，不在Microsoft/Boot再生成grub.cfg副本。每个实际安装平台始终只有一份主grub.cfg，不生成DAT镜像，不部署无作用的占位logo.png。显示主Logo与角色已经合成到背景图中。


## 四种典型组合

| 使用方式 | 实际启动资源 |
| --- | --- |
| UEFI：单静图、无动图 | Microsoft/Boot下shim/所选GRUB/MokManager，EFI/fedora/grub.cfg，AnimeBootNeo/theme；没有Linux和bootstate.env |
| Legacy：单静图、无动图 | 根bootmgr桥、AnimeBootNeo内GRUB核心/主配置/字体/Windows备份/theme；微型MBR；没有Linux和环境块 |
| 任意平台：多静图、无动图 | 上述对应平台资源，加多背景/style和bootstate.env；仍没有Linux |
| 任意平台：启用动图 | 对应平台资源，加bzImage、环境块及一个或多个initramfs；多动画共用一份内核 |

## manifest.json字段逐项

- `format/app_version/application`：当前制作格式、显示版本及程序名。格式不是GRUB版本。
- `legacy_method/locator/bound_boot_mode/boot_binding`：文件桥方法、定位方式及目标绑定。未绑定结果尚未选定真实分区；Legacy绑定含文件系统类型与UUID。
- `config_project`：重新生成目标配置需要的参数副本，包含分辨率、时长、动画参数、画布倒计时模式和过渡设置；不是完整可编辑工程。
- `project`：面向验证/诊断的实际启动摘要，含静图数量、所有控件类型和编译后的交接策略。
- `animation`：是否启用、实际编码/帧数/尺寸/播放参数。顺序轮换有`rotation=sequential`和`items`，每项含自己的initramfs路径和实际统计；顶层frame_count是总和。
- `runtime`：主动画initramfs的大小、SHA256和编码信息；多段的详细结果在各items.runtime。
- `grub_mode/grub_versions`：默认或备用，以及BIOS/UEFI对应的完整Fedora发行版本号。
- `env_path`：需要状态时为AnimeBootNeo/bootstate.env，否则为空。
- `boot_ui`：生成文件的静默菜单/A20/横幅策略与EFI字节不修改的记录。
- `files`：相对InstallPayload路径→size、sha256。安装前后重新核对；它不是数字签名，不能证明外来manifest可信。

## bootstate.env：为什么写、何时写

文件固定1024字节，以`# GRUB Environment Block`开头，键值行后由`#`填满。`neo_once`允许0/1；两个轮换序号允许0—7。
静图选择后推进neo_static_rotation。真正启动Linux之前保存neo_once=1及下一段neo_rotation；播放器结束重启，GRUB读到neo_once便清零并直接启动Windows。
消费one-shot发生在轮换选择之前，因此不会因播放后的重启多推进一次。Esc直接Windows不推进动图。
仅静图多画布只用静图序号，其余键保持0。损坏状态必须被验证发现，不从任意未校验数据计算磁盘路径。
GRUB对环境块的持久保存依赖目标文件系统/设备支持；本工具支持的绑定路径为FAT16/FAT32/NTFS，Linux没有更新该文件的职责。

## AnimeBootNeo.Backup：安装器生成的文件

`state.json`记录`phase`（prepared/complete等）、引导方式、所有文件路径、原来是否存在、原始与安装SHA256、原属性、环境路径、目标绑定及固件条目身份。
`files/<原相对路径>`保存被替换文件的原始内容；并不是每个动画都复制一份。Windows备份也可成为正常交接入口，不能当缓存删除。
Legacy另外有`original-mbr.bin`与`installed-mbr.bin`，保存原/安装后512字节，以便核对和恢复；真正安装只改变0..439代码区。
固件条目记录保存Boot编号/身份摘要以及修复条目，用于只撤销本工具的变更。不会仅凭名称删除别人的Windows入口。
禁用先恢复Windows并验证，再移除所属目录、共享路径中的本工具资源以及记录。恢复失败保留恢复材料；不要单独删state.json。

## initramfs里面实际是什么

目录dev、proc、sys、tmp、AnimeBootNeo；根`init`是PID1；`AnimeBootNeo/player`是播放器；动画数据为`animation.anbf`或`animation.anbf.jcx`。
QOI是逐帧无损；JPEG以32帧为块进行独立XZ压缩与索引，便于播放时并行解压。不是.mp4视频文件，也不是EFI分区镜像。
PID1挂载内存/伪文件系统、启用可用显示接口并启动播放器；播放器完成后重启。磁盘读写、Windows一次接力与轮换状态由GRUB承担。
没有额外NVMe/SATA磁盘驱动包；官方内核内建能力不能在不改变签名的条件下任意裁掉。

## 清理规则

启动分区的theme资源只包含本次配置需要的贴图。透明circle-center.png是圆环控件输入，不是无用可见logo。
同内容背景和控件贴图去重；用户主Logo、角色、文字已经合成进back PNG。
每个平台仅部署一份主grub.cfg；多style是多画布主题，不能与重复启动配置混为一谈。
构建目录core.img、manifest.json、boot.img和预览PNG不会按原样全放进ESP；具体由平台绑定和部署事务决定。
