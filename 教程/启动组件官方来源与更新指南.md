# 启动组件官方来源与更新指南

## 一、版本与“已签名”的准确含义

默认 BIOS/UEFI **GRUB2 均为 Fedora 2.12-64.fc44**；备用 BIOS/UEFI **均为 Fedora 2.12-56.fc44**。两档共用 shim 16.1-7 和 Linux 7.2.7-200.fc44.x86_64。GRUB4DOS 0.4.6a 是 BIOS 最前面的独立文件桥接加载器，不是这两档 GRUB2 核心，也没有在 UEFI 路径中使用。

界面只提供“默认GRUB”和“备用GRUB”，用于比较所选GRUB在目标机器上的显示与加载表现。两档使用同一shim和Linux内核，通常先用默认。

UEFI 路径：固件 → Fedora shim（工程名 bootmgfw.efi）→ Fedora 签名 GRUB → Fedora 签名内核 → 本工程 initramfs 中的 PID1/播放器 → 重启后返回备份的 Windows EFI 入口。

BIOS 路径：本工程微型 MBR → 原 Windows 分区引导扇区 → 根目录 bootmgr 名称下的独立 GRUB4DOS 文件桥 → 普通文件 AnimeBootNeo/grub2.lnx → 配对的 Fedora GRUB2 BIOS 核心 → 同一 Fedora 内核/initramfs → 重启后加载 Windows bootmgr 备份。

重要区别：

* shim、MokManager、UEFI GRUB 和 bzImage 有 PE/Authenticode 签名；五个文件的签名和 PE 内容摘要已有本地验证记录。
* BIOS MBR、grldr、BIOS .mod/.img 不走 UEFI Secure Boot，不能称为“已签名传统引导文件”。
* 本工程 init/player 是 Linux 用户态 ELF，自定义 initramfs 是数据归档；它们不是签名 EFI，也不是签名 .ko。本架构未对整个自定义 initramfs/动画做独立的 Secure Boot 签名认证，不能把“内核已签名”写成“全部播放内容已由固件认证”。
* 官方下载地址、SHA-256、RPM包签名、PE签名、固件db/dbx/SBAT接受策略是不同检查。已验证PE/CMS内容，不等于所有主板必定接受。实测结果以实际测试范围为准；目标实机固件及完整Windows交接仍须实测。
* 本文件只列本包实际采用的 x86-64 签名链。i386-pc 指 BIOS GRUB 目标，并不表示内核为 32 位；没有打包 Fedora 全架构的 IA32/ARM64 EFI 资源。

官方说明：[Fedora Secure Boot](https://fedoraproject.org/wiki/Secureboot)、[shim 上游](https://github.com/rhboot/shim)。Fedora 二进制应从 Fedora 官方 RPM 提取并保持原字节；仅下载上游源码自行编译，不会自动获得 Fedora 或微软签名。

`.mod` 是 BIOS GRUB 功能模块；`.lst` 是命令/依赖/文件系统索引；`.img` 是上游启动模板。二者都不是 UEFI 已签名文件目录。目录保留当前显式模块及递归依赖闭包（每档46个模块）和必要链接模板，安装时不把它们整目录塞进 ESP 或分区前空隙。

本工程与官方输入的差异只有明确记录的自编 `neo_vbe.mod`，以及 `moddep.lst` 追加 `neo_vbe: video` 并将行尾规范为 CRLF。自编模块源码是 `assets/grub/neo_vbe.c`；用于将当前 BIOS VBE 显示模式交给 Fedora Linux，许可证 GPL-3.0-or-later。`tools/rebuild_neo_vbe.py` 可用对应 GRUB 源码头文件和 Zig 重建两档；升级到不同上游版本时必须先审查模块 ABI，不能照搬旧 .mod。

当前 `animeboot_neo/builder.py` 的 grub-mkimage 显式模块列表是（外层等待路径另加sleep）：

```text
biosdisk part_msdos fat ntfs normal configfile search search_fs_uuid
loadenv test echo reboot halt linux chain ntldr gfxterm gfxmenu
vbe neo_vbe png jpeg font
```

工具还会自动合入以上模块的依赖。未选择的 ATA/AHCI/文件系统/网络模块不会因为目录里存在就全部安装。最终 `core.img` 是本程序按模块列表生成，和官方 `lnxboot.img` 组成普通文件 `AnimeBootNeo/grub2.lnx`。传统启动的大资源不存到首分区前的空白扇区。

musl libc 来自 Zig 0.13.0 工具链的捆绑实现，许可证 `licenses/musl-COPYRIGHT`；目前只锁定工具链，没有独立记录 musl release 号，因此不杜撰一个版本号。上游：[musl](https://musl.libc.org/)。普通 Windows `build.py` 使用已锁定的 ELF，不会现场下载/编译这些 C 库。

微型 MBR 使用 NASM 2.16.03 编译。官方版本入口：[NASM 2.16.03 Windows x64](https://www.nasm.us/pub/nasm/releasebuilds/2.16.03/win64/)。可重建：

```text
nasm -f bin assets/legacy/mbr.asm -o assets/legacy/mbr.bin
```

当前播放器使用 `Zig cc -target x86_64-linux-musl -O3 -static -pthread -s`，链接对应libjpeg.a、liblzma.a和libm；PID1独立静态编译。可执行 `python tools/rebuild_native_player.py --toolchain "已有工具链目录"`，所需Zig及静态库目录结构见脚本，依赖不会自动下载。build_player_mt.sh是通用cc入口，不锁定系统库版本。重建后须同步刷新CSV、provenance与锁记录；自有源码和ELF的当前大小/hash以本包CSV和components.lock.json为准，以实际构建产物为准。

## 八、更新组件的完整流程

1. 按官方构建NVR取得二进制RPM及对应SRPM；每档UEFI/BIOS的Fedora完整版本号必须一致。不要只比较“2.12”。保存URL、包摘要和原包内路径。
2. 从RPM提取shim、MokManager、UEFI GRUB和vmlinuz。只允许必要重命名，不能修改任何签名PE字节；本地重编译不会继承Fedora签名。
3. 验证RPM来源、PE内容摘要、CMS签名及证书，再检查shim内嵌信任与SBAT/固件db、dbx。单个文件有签名不代表组合链或每台固件会接受。
4. 替换内核时保存对应config、modules.builtin，检查XZ/newc支持、内建显示接口与Secure Boot lockdown。播放器资源都在RAM，不新增磁盘驱动来读取动画。
5. BIOS模块按builder.py的显式列表及moddep递归闭包筛选；sleep为条件路径也必须保留。kernel.img、diskboot.img、lnxboot.img、lzma_decompress.img各有生成用途，不能仅根据.mod依赖删除模板。
6. neo_vbe.mod属于自编BIOS模块，需按对应GRUB头文件/ABI重编。quiet_boot的精确字节匹配失效时先审查对应源代码，再调整；不能盲猜偏移。
7. GRUB4DOS更新须核查preset菜单、A20静默位、Linux引导协议和FAT/NTFS读取。保留确切commit源码及许可证。未签名BIOS文件不影响UEFI签名，但也不能称为签名文件。
8. 更新components.lock、grub-pairs、逐文件CSV、来源JSON和许可。修改来源和登记新哈希必须是审计结果，不能用它掩盖未知二进制变化。
9. 运行单元/Qt界面/默认备用核心构建检查，再用一次性虚拟磁盘测试UEFI安全启动、BIOS、静图/动图/Esc/调试/多次轮换/Windows交接。
10. 进行实机安装—验证—禁用及完整Windows启动测试，覆盖实际固件与磁盘。公开分发源码/EXE前核对第三方源码与许可交付要求。

## 九、重建本工程的原生资源

`tools/rebuild_native_player.py --toolchain <工具链根目录>` 使用Zig0.13.0、libjpeg-turbo3.1.2和XZ5.8.1，生成静态x86_64-linux-musl PID1/播放器。
工具预期目录：`zig/zig-windows-x86_64-0.13.0/zig.exe`、`jpeg/libjpeg-turbo-3.1.2/src`、`jpeg-build`、`xz/xz-5.8.1/src/liblzma/api`、`xz-build`。
jpeg-build需有相应配置头和libjpeg.a，xz-build需有liblzma.a；它们必须用同一目标工具链构建，不能链接Windows库或主机架构库。
`assets/linux/build_player_mt.sh`提供Linux本机静态链接命令；它读取系统提供的对应库，所以需自行确保版本/许可一致。
`tools/rebuild_neo_vbe.py`重建BIOS显示交接模块；`nasm -f bin assets/legacy/mbr.asm -o assets/legacy/mbr.bin`生成512字节微型MBR。
重建工具会更新它负责的锁项；发布前仍应同步来源CSV/JSON并检查真实显示效果。自有代码许可见根目录LICENSE；依赖保持原许可。

## 十、资源解释与签名边界

工程名`assets/fedora/bootmgfw.efi`是Fedora shim。实际Windows bootmgfw.efi和bootmgr来自目标系统，属于Windows，不随工程分发。
静图只用GRUB；动图才加载内核/initramfs。initramfs内有自编用户态程序及动画，不宣称其整体由UEFI签名认证。
UEFI使用已签名GRUB内置GOP/UGA及主题能力，不能任意加载自行编译的EFI模块。GOP不等于硬件加速或防撕裂承诺。
当前PNG主题的中文是Windows侧预渲染，UEFI不安装外置PF2；Legacy仍使用unicode.pf2。该字体源于Unifont13.0.06，见Fedora SRPM的Source4与licenses中的字体许可/源码。
逐文件部署用途见“启动分区文件详细说明”；制作阶段资产用途见“组件目录用途”。
