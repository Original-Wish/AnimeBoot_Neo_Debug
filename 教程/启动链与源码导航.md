# 启动链与源码导航

## 从界面到Windows

`app.py → qt_gui.MainWindow → BuildWorker → builder.build_payload → deployment安装事务`。
构建阶段复制工程快照，在普通输出目录渲染全部静图并制作每段动画；GUI可以继续切换画布。安装阶段依据本次构建的manifest绑定目标，成功说明读取本次快照。

UEFI：固件Microsoft/Boot入口 → Fedora shim → 同目录Fedora GRUB → EFI/fedora/grub.cfg → 静图 → Windows备份，或者签名Linux+initramfs → 播放 → 重启 → GRUB消费neo_once → Windows备份。
Legacy：固件 → 本工程微型MBR → 原活动分区VBR → 根bootmgr（GRUB4DOS）→ AnimeBootNeo/grub2.lnx（GRUB2）→ 主配置 → 同一Linux播放器或Windows bootmgr备份。
MBR代码不是动画标记存储。GRUB写环境块，Linux只读已装进内存的资源；不要给播放器增加磁盘访问来维持轮换。

## 模块分工与应保持的约束

| 源码 | 阅读重点 |
| --- | --- |
| project.py / scenes.py | 默认值、格式、校验、画布同步。对象字段是每画布，分辨率与启动参数全局。 |
| theme.py / canvas_geometry.py | 单张背景渲染、动态控件主题、资源去重；旋转局部坐标、锚点和正方形约束。 |
| rotation.py / rotation_dialog.py | 主动画+列表、只估算所选编码、缓存批准、关闭/编辑失效资源的交互。 |
| theme_package.py | 资源遍历/映射与防越界、大小/hash校验、暂存解包发布。 |
| animation.py / video_extract.py / image_extract.py | FFmpeg/GIF时间轴与有界并行，取消及子进程生命周期。 |
| archive.py / runtime.py | FileSlice流处理、ANBF/JCX索引、newc对齐、initramfs组成。 |
| builder.py / resources.py | 锁定资源、双平台未绑定产物、绑定/校验与原子发布。 |
| grub_config.py | one-shot消费顺序、静图策略、Esc、静图与动图独立轮换、安静启动。 |
| legacy_file.py / quiet_boot.py | BIOS文件桥与字节布局校验，只改生成副本，不动已签名文件。 |
| deployment.py / boot_space.py | 文件所有权、备份事务、实际空间、恢复与目录清理。 |
| windows.py / windows_efi.py | 原生API、PE身份、BitLocker、BCD与固件条目身份匹配。 |
| fonts.py / qt_gui.py / ui_effects.py | 字体缓存、GUI线程、后台worker、滚动交互与皮肤。 |
| assets/linux/*.c、*.h | PID1、帧解码、fbdev/DRM显示、两页画布诊断。 |

具体函数行号见源码函数索引.csv。关键模块头部及关键入口附有中文原理注释；修改时以对应实现和测试断言为准。

## 状态与线程

编辑器project、BuildWorker.project是不同对象。构建结果携带project_snapshot，安装expected_timeout及成功报告不能读取用户随后编辑的project。
Qt所有控件更新由主线程处理；worker用signal回传字典/文字。QThread结束前不能销毁其窗口，结束信号安排deleteLater避免悬空对象。
轮换窗口确定保存前不提交project，缓存属于主窗口进程内状态。取消可以保留有效估算而不提交编辑结果，签名不匹配就不复用。
可用空间可能随外部操作变化，任何估算批准都只是预估；真正写盘前重新核对。

## 开发验证顺序

先验证数据/渲染/编码函数，再跑GUI交互与快照测试。启动配置须由grub-script-check检查，默认/备用BIOS核心都要生成。
改变模块/内核/播放器时，分别测试UEFI安全启动和Legacy，验证真实画面和接力变量；只看到日志“播放完成”不能证明屏幕显示正确。
部署测试在临时目录与mock平台接口进行；磁盘与固件操作不能对开发主机自动尝试。安装器应始终先保留可恢复状态。
